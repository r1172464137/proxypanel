# 产品级私有面板：候选用户故事

状态：本轮候选需求，不是实现或验收报告。角色仅为用户明确接受的管理员、成员；不新增权限角色。角色来源：[本轮决策账本](../../decision-log/product-readiness.md) `DEC-product-readiness-003`；现有产品说明对照：[角色与可见范围](../../../docs/design/product.md#2-角色与可见范围)。现无正式 `_roles.md`，不伪造链接、不在本阶段发布正式角色文档。

## 管理员交付旅程

### US-PR-001：通过受保护入口启动服务
**优先级：P0**
- **作为**管理员，**我希望**按一套完整说明启动面板并登录，**从而**不用猜测前端、证书和后台分别归谁管理。
- **场景：首次部署成功**
  - Given 已准备部署说明要求的域名、证书和依赖
  - When 管理员按所选部署方式启动并访问面板
  - Then 可通过 HTTPS 登录，刷新页面后仍正常；说明覆盖面板托管前端与独立静态托管两种方式。
- **场景：前置条件缺失**
  - Given 证书、关键配置或依赖未就绪
  - When 管理员检查启动结果
  - Then 能定位具体缺失及处理步骤；页面或说明不把进程存活等同服务可交付，不建议以公开明文方式绕过问题。

### US-PR-002：沿首次设置路径完成初始化
**优先级：P1**
- **作为**首次使用的管理员，**我希望**看到已完成、尚缺的配置及下一步入口，**从而**不用在多张空列表之间猜顺序。
- **场景：全新环境**
  - Given 尚无可交付服务
  - When 管理员进入工作台
  - Then 能沿服务器、节点、节点组、服务方案、成员开通、连接验证逐步完成设置，并可返回修改。
- **场景：部分配置已存在**
  - Given 环境已有部分配置
  - When 管理员再次进入设置路径
  - Then 进度来自实际配置，已有对象可复用，不重复创建、不以示例数据标记完成。

### US-PR-003：接入服务器并判断真实状态
**优先级：P0**
- **作为**管理员，**我希望**接入服务器后看懂它是否已连接、节点是否运行，**从而**知道能否继续交付。
- **场景：接入成功**
  - Given 已添加服务器并准备管理程序
  - When 管理员使用有效注册码完成接入
  - Then 页面展示真实连接和同步结果，下一步可直接配置节点；复制注册码不等于接入成功。
- **场景：接入失败或离线**
  - Given 注册码失效、连接中断或状态未获取
  - When 管理员查看服务器
  - Then 页面分别说明未接入、离线或未知，提供重新注册/查看诊断入口，不显示为节点可用。

### US-PR-004：配置并安全修改节点
**优先级：P0**
- **作为**管理员，**我希望**用清晰表单建立连接入口，并在需要时使用高级配置，**从而**常用设置易填、复杂设置也不会被无声丢掉。
- **场景：创建与编辑成功**
  - Given 选择了支持的连接方式并准备必要材料
  - When 管理员创建节点，随后只修改名称
  - Then 能保存有效配置；原有证书、传输参数与密钥保持不变，默认不要求重新输入已有秘密。
- **场景：材料错误或更换密钥**
  - Given 必要证书缺失、参数不兼容或管理员要更换密钥
  - When 提交设置
  - Then 错误定位到对应输入；换钥显示影响并保持配对一致；不能用“保存成功”代表客户端连接已验证。

### US-PR-005：建立可复用服务方案
**优先级：P0**
- **作为**管理员，**我希望**把可用节点、每人额度和有效期规则组织成服务方案，**从而**为多位成员一致地开通服务。
- **场景：方案可交付**
  - Given 已有可选节点和节点组
  - When 管理员创建服务方案
  - Then 能看懂成员将获得哪些节点、多少额度、何时到期或重置；服务方案与个人订阅链接使用不同名称。
- **场景：影响已有成员**
  - Given 方案已分配给成员
  - When 管理员修改会改变访问权限的内容
  - Then 先显示影响及生效时间；不能无声清空已用量、个人覆盖或当前周期。

### US-PR-006：创建成员或通过邀请开通
**优先级：P0**
- **作为**管理员，**我希望**直接开通或邀请成员，并清楚指定是否分配服务，**从而**交付结果与邀请说明一致。
- **场景：带服务的邀请**
  - Given 邀请明确包含有效服务方案
  - When 受邀者注册
  - Then 账号与服务一并正确建立，额度、期限和连接信息一致；不再要求重复人工绑定才能补齐开通。
- **场景：无服务或邀请失效**
  - Given 邀请未分配方案，或已经过期/撤销/达到使用上限
  - When 受邀者尝试加入
  - Then 无服务者可登录查看待开通说明；失效邀请不能继续注册，不泄露他人资料，页面给出联系邀请人的下一步。

## 成员使用旅程

### US-PR-007：从首页完成客户端导入
**优先级：P0**
- **作为**成员，**我希望**进入页面就知道服务是否可用，并按客户端指引完成导入，**从而**不必先理解协议配置和凭据结构。
- **场景：首次连接**
  - Given 已开通且有兼容节点
  - When 成员选择实际使用的客户端
  - Then 能按明确步骤复制链接、扫码或下载配置，并知道如何更新订阅、选择节点、连接和检查结果；手机也能完成。
- **场景：不兼容或不可用**
  - Given 某格式不能表达节点配置，或成员尚无权限
  - When 成员查看导入区
  - Then 给出具体原因和可执行替代路径；不提供虚假可用链接，不把打开订阅页面当成实际连通。

### US-PR-008：看懂额度、期限及不可用原因
**优先级：P0**
- **作为**成员，**我希望**在主页面看到剩余额度、有效期、下次重置及当前状态，**从而**不用在几个技术页面拼接原因。
- **场景：正常使用**
  - Given 已有有效服务
  - When 成员打开服务首页或用量页
  - Then 能区分已用、总额、剩余、不限量、有效期和重置时间；未知数据不显示为零。
- **场景：超额/到期/暂停/无方案**
  - Given 其中一种情况导致不可用
  - When 成员打开页面
  - Then 直接看见对应原因及恢复方式，仍可查看账号和历史；默认不展示内部错误码或权限判定原始数据。

### US-PR-009：管理密码、会话和连接信息
**优先级：P0**
- **作为**成员，**我希望**安全修改密码、退出其他设备和更新连接信息，**从而**在不误操作的情况下保护账号。
- **场景：正确操作**
  - Given 已登录
  - When 修改密码或明确确认重置连接信息
  - Then 当前操作会话和其他会话按说明处理；“重置订阅链接”与“重置连接凭据”分别说明影响，按钮与动作一致。
- **场景：输入或网络错误**
  - Given 当前密码错误或结果尚未确认
  - When 提交操作
  - Then 在原处显示可理解反馈，不因输错当前密码误踢有效会话，不把未确认结果显示为已完成。

## 管理员日常运营与可靠性

### US-PR-010：批量变更可预览、可追踪、可恢复
**优先级：P0**
- **作为**管理员，**我希望**提交前看清每人的变化、提交后追踪结果，**从而**不会把一次请求成功误认成所有节点已更新。
- **场景：确认并完成**
  - Given 已选择明确对象和操作
  - When 查看影响并确认
  - Then 可看见变更前后、立即断线/下周期生效等必要后果，并进入可持续查看的结果记录。
- **场景：并发或响应丢失**
  - Given 他人已修改对象、预览过期或提交后响应丢失
  - When 管理员重试/核对
  - Then 不覆盖他人变更、不重复执行；结果不确定时先核对同一次操作，而不是直接再次创建变更。

### US-PR-011：暂停与恢复访问真实生效
**优先级：P0**
- **作为**管理员，**我希望**暂停、到期、超额与恢复操作真实改变访问能力，**从而**权限状态不只是页面文字。
- **场景：在线撤权与恢复**
  - Given 节点可通信且成员已有连接
  - When 管理员暂停访问并在之后恢复
  - Then 按现行验收窗口验证新连接和已有连接都被阻止；恢复后正确权限与连接能力恢复，不回退到已撤销凭据。
- **场景：离线或校验缓慢**
  - Given 节点离线或其他节点配置校验异常
  - When 已知到期到达或节点收到收紧授权
  - Then 不因无关节点拖延而无限保留旧授权；未完成状态明确可见，不假报撤权完成，并说明共享节点短暂断线的影响。

### US-PR-012：定位异常并安全重试
**优先级：P0**
- **作为**管理员，**我希望**从工作台直接进入需要处理的异常，**从而**不用在心跳、实例、任务、事件之间自行猜原因。
- **场景：已知故障**
  - Given 存在离线、配置失败或用量上报积压
  - When 管理员查看工作台并进入详情
  - Then 能看见受影响对象、当前影响、最近证据和可执行处理；技术详情可展开，但处理入口不被说明文字淹没。
- **场景：失败重试**
  - Given 一个节点配置错误或旧任务晚到
  - When 修复并重试
  - Then 不把旧回执当新任务成功，不影响无关节点；回滚运行与目标已更新必须区分，不能永久假绿。

### US-PR-013：用量、周期与历史补报可信
**优先级：P0**
- **作为**管理员和成员，**我希望**用量不重复、账期不重叠、恢复后额度准确，**从而**能依据页面决定是否还能使用。
- **场景：边界与重发**
  - Given 有跨周期流量、网络重试或修改后的下一周期规则
  - When 数据到达并进入新周期
  - Then 不重复收费、不丢已确认数据；历史按发生区间归属，不无声移入当前周期；应恢复者实际可连接。
- **场景：资料不足或时钟异常**
  - Given 历史规则无法证明或数据时间异常
  - When 系统接收或管理员核对
  - Then 不盲目补算、不自动放宽授权，异常和需要核对的内容可追踪；上线前必须完成受影响资料核对。

### US-PR-014：维护与恢复不复活旧权限
**优先级：P0**
- **作为**管理员，**我希望**按明确核对流程恢复服务，**从而**备份恢复不会把已停用成员重新放回去。
- **场景：完成核对后恢复**
  - Given 数据已从备份恢复且处于核对状态
  - When 管理员核对权限、账本及节点接受状态并解除维护
  - Then 服务按核对后的授权恢复，界面能追踪未恢复的节点。
- **场景：未核对完成**
  - Given 系统仍处于恢复核对中
  - When 尝试普通授权变更、注册、邀请或重置连接信息
  - Then 普通变更被阻止，账号救援与必要遥测按既定规则可用；页面给出维护说明而不是假装成功。

### US-PR-015：在不同屏幕与异常状态下完成任务
**优先级：P1**
- **作为**管理员和成员，**我希望**页面在手机、桌面、亮暗主题及异常状态下仍能操作，**从而**不依赖某个理想屏幕或网络。
- **场景：正常操作**
  - Given 使用键盘或窄屏设备
  - When 进入核心页面、打开弹窗和操作表单
  - Then 主操作可见可达、焦点合理、字段有标签、状态不只靠颜色，内容不横向溢出。
- **场景：加载/空/错**
  - Given 请求未完成、没有数据或加载失败
  - When 查看页面
  - Then 三种情况可区分，各自有真实下一步；失败内容不被空选择器或演示数据掩盖。

### US-PR-016：升级后仍可交付并可核对退回
**优先级：P0**
- **作为**部署管理员，**我希望**升级前知道备份和兼容条件、升级后能核对完整服务，**从而**不因一次发版丢数据或旧权限复活。
- **场景：受控升级**
  - Given 已有有效备份和明确候选版本
  - When 按说明升级
  - Then 账号、权限、周期、账本和必要状态保留；两种前端托管均能刷新和登录，前后端版本一致。
- **场景：升级失败**
  - Given 校验、迁移或启动未完成
  - When 管理员查看结果并选择处理
  - Then 失败明确可见，已有数据不被盲目覆盖；软件版本退回与数据库恢复分别说明，不以旧数据恢复重新放行。

### US-PR-017：权限与秘密不会因体验优化泄露
**优先级：P0**
- **作为**成员和管理员，**我希望**不同角色仅看到自己应有的信息，**从而**简化页面不会降低安全边界。
- **场景：合法查看**
  - Given 使用自己的账号
  - When 查看服务、使用量或管理对象
  - Then 内容属于许可范围，敏感值默认隐藏，复制或重置时有明确含义。
- **场景：越权或泄露风险**
  - Given 尝试访问他人信息、使用失效会话或拉取不属于本机的管理对象
  - When 访问或提交
  - Then 被拒绝，不因界面隐藏或缺少默认值而放行；页面、日志和验收产物不暴露密码、私钥或完整订阅令牌。

### US-PR-018：列表与批量范围可信
**优先级：P1**
- **作为**管理员，**我希望**对象增多后仍能找到全部目标并看清选择范围，**从而**不会把截断列表当作全部成员或全部节点。
- **场景：查找与选择**
  - Given 对象数量超过单页显示数量
  - When 管理员搜索、切页或选择批量对象
  - Then 可访问符合条件的全部结果，数量与选择范围一致；按筛选条件执行前能看到实际目标集合。
- **场景：查询失败或结果变化**
  - Given 搜索未完成、结果变化或请求失败
  - When 管理员尝试批量提交
  - Then 不拿旧选择范围或前一页结果冒充新结果，不显示假总数，影响发生变化时要求重新核对。
