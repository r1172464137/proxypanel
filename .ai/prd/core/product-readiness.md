## 2. 范围界定

### 2.1 包含

1. 管理员“接入资源—配置服务—开通成员—跟踪生效—处理异常”的完整旅程。
2. 成员“加入—查看服务状态—导入客户端—查看用量—保护账号”的完整旅程。
3. 主导航、页面信息层级、首次设置、表单、空/错/加载状态及全站文案的统一。
4. 节点、节点组、服务方案、成员、邀请、批量操作、用量、运行状态、告警、审计与设置的可理解表达。
5. 保留高级配置能力，但默认页面以任务和结果组织；高级内容不能在保存时丢失。
6. 安全、权限、计量、周期、异步生效和故障恢复的正确性，及完整端到端验收。
7. 可部署、可升级、可备份恢复的交付说明；前端两种托管方式均有可复现路径。
8. 核心列表的真实查询、逐页访问和明确批量范围，不把截断结果冒充全部。

### 2.2 不包含

- 支付、订单、余额、退款、优惠券、返佣、商城、人工收费业务流程。
- 新增多租户、复杂角色权限、工单系统、客户端软件或通用远程终端。
- 未选定的共享流量池、跨节点全局限速、设备限制、中转拓扑管理。
- 为“商业感”加入无后端支撑的图表、假的在线人数、虚构 SLA、占位按钮或模拟成功。
- 一并更换技术栈、重新发明全部基础组件，或未经用户决定更改软件许可证。
- 全协议、全客户端、全平台兼容承诺。

### 2.3 与现有资料的关系

本草案对现有产品说明中的默认界面、任务路径、术语和验收表达作增量替换；不因页面改名改变既有角色、授权继承或配额业务规则。现有产品规格是参考草案，不是实现清单。接口与部署事实由各自参考文档及源码核验，不能把旧提案与候选目标混成已交付事实。

## 3. 需求概述

### 3.1 问题陈述

当前要解决的不是“文字不够高级”，而是使用者需要理解内部实现才能完成任务：同一个“订阅”既指规则又指链接，页面大量解释系统没有做什么，保存和生效的反馈容易混淆，成员拿到链接后仍需自行寻找导入方法。

目标是让管理者能交付一个可用服务，让成员能独立开始使用，让异常有可执行的下一步。保留必要风险说明，但将其放在真正相关的操作和状态旁边，不用每页大段工程声明代替产品设计。

### 3.2 成功信号

- 从全新环境完成开通旅程，不需用户自行发现隐藏依赖或重复完成邀请里已指定的分配。
- 成员从首页完成受支持客户端导入；无权限、不兼容、到期和超额各自有明确原因及下一步。
- 界面中的保存、同步、实际连接和用量均有对应证据，不因一个成功提示而误判整条链路。
- 原始配置不因编辑界面简化而丢失；安全操作不因追求少点击而失去保护。
- 所有故事都有成功及关键异常的实际验收记录；失败和未知不能被通过率掩盖。

不虚构用户访谈、付费意愿、留存提升或节省时长。本轮成功先以可重复完成的任务和真实链路为证据，后续再用实际使用反馈评价效率。

## 4. 业务规则与状态

### 4.1 统一术语

| 产品表达 | 含义与边界 |
|---|---|
| 服务方案 | 管理员配置的节点范围、每人额度与有效期等授权规则；不代表付费套餐 |
| 订阅链接 | 成员交给客户端获取配置的个人链接，不等于服务方案本身 |
| 服务器 | 承载节点的机器档案 |
| 管理程序 | 在服务器上执行配置与上报状态的程序；技术详情中保留 Agent 原名 |
| 节点 | 成员实际连接的入口，协议名称仅在需要选择或诊断时展示 |
| 节点组 | 用于组织可授权节点的分组，不变更现有授权单位 |
| 同步任务/变更记录 | 区分一次业务变更与它在节点上的执行结果，不能混成一次请求是否成功 |
| 重置订阅链接 | 旧链接无法继续下载配置，不冒充“立即切断全部现有代理连接” |
| 重置连接凭据 | 更新实际连接凭据，明确告知旧连接及相关节点的影响 |

术语替换首先针对界面，不擅自改底层兼容契约。专家需要的协议、证书、原生配置和诊断信息保留在明确的高级入口。

### 4.2 开通与邀请

- 邀请创建时明确显示是否分配服务方案。
- 带服务方案的邀请应在加入时完成一致的开通；无方案邀请只建立账号并明确显示待开通。
- 失效、撤销、超出次数或不再允许加入的邀请不可继续消费。
- 复制邀请码不等于对方已加入；加入成功也不等于节点同步或真实连接已经完成。
- 一次性秘密使用前明确提示保存；遗失时提供安全的重新签发/撤销路径，不承诺重新读取已不可恢复的旧秘密。

### 4.3 保存与实际生效

| 状态 | 默认展示 | 可以宣称什么 |
|---|---|---|
| 已确认保存 | 已保存，正在同步 | 业务设置已保存，不代表所有节点已更新 |
| 待同步 | 还有节点等待更新 | 给出对象、最近状态及查看进度入口 |
| 部分完成 | 部分节点已更新 | 展示成功、等待和失败对象，不用整批绿色成功覆盖细节 |
| 同步失败/超时 | 尚未完成，请处理以下问题 | 保留原始结果与可操作下一步 |
| 回滚运行 | 正在使用上一份可运行配置，目标变更未完成 | 不与“当前目标已生效”混称正常 |
| 结果未确认 | 正在核对提交结果 | 不直接判失败或成功，不诱导重复创建变更 |
| 数据未知/读取失败 | 暂时无法获取状态 | 不显示零用量、零对象或健康状态作为替代 |

进程存在、管理程序在线、端口可达和真实客户端连接是不同事实。没有连接验证证据时，不标为“连接已验证”。

### 4.4 权限、周期与计量

- 保留管理员与成员边界；普通成员不因看到管理入口就获得管理权限。
- 个人额度和有效期不能绕过账号停用、服务暂停、节点禁用或授权范围。
- 当前周期与下一周期规则清楚区分；不能通过界面操作无声重叠账期或立即清零历史。
- 历史流量按发生区间归属，重复上报不重复计量；无法证明的历史不能悄悄挪到本周期。
- 超额后的恢复必须恢复实际可连接能力，而不只是恢复页面标签。
- 在线撤权、通信恢复后的撤权及已下发的到期按既有 60 秒验收口径验证；这不是对任意规模和不可终止操作系统进程的生产 SLA 承诺。离线等待、停止失败和超时必须可见。
- 共享节点重启可能短暂影响同节点其他连接；管理员确认时说明实际影响，成员端不泄露其他成员身份。
- 恢复核对期间冻结普通授权写入，账号救援及必要遥测按明确例外保留，不能因读页面而新增授权材料。

### 4.5 删除、升级与恢复

危险动作使用能表达实际效果的名称，确认框展示对象和影响，不把归档、永久删除、禁用及重置混称。

升级不能无声改变历史账本与授权。资料不足时先阻断升级/交付并核对，不直接接受任何候选迁移里未经审查的自动暂停或自动补算策略。软件退回与数据库恢复分开说明；恢复流程不能让已撤销权限复活。

## 5. 功能需求与目标旅程

### 5.1 管理员工作区

- 工作台先展示需要处理的事项和当前交付进度，再展示统计口径；不以“这些数字不代表真实运行”占据主标题。
- 导航按成员与服务、资源、运行监控、系统组织；详情从所属对象进入，批量操作从目标列表发起并能回到结果记录。
- 首次设置使用真实配置状态指引下一步，不用不可验证的勾选完成或隐形自动配置。
- 服务方案展示节点范围、配额、期限与生效时点；默认与个人覆盖并列可读。
- 邀请、注册码和重置动作分别交代有效期、是否仅显示一次、遗失后的安全处理路径。
- 普通表单优先结构化输入；高级原生配置有清晰入口和无损保存约束。

**目标旅程：** HTTPS 部署 → 接入服务器 → 创建并验证节点 → 组织节点组 → 建立服务方案 → 创建/邀请成员 → 成员导入并产生真实流量 → 核对用量与同步结果。

### 5.2 成员工作区

- 首页优先显示“能否使用、剩余多少、何时到期/重置、下一步怎么连接”。
- 导入按实际客户端组织，提供复制、二维码、下载及明确步骤；一键导入只在目标客户端/平台已经验证时启用，不做无效按钮。
- 状态摘要就地解释无方案、暂停、到期、超额、不兼容与维护，不要求成员阅读原始返回。
- 用量明示单位、周期和数据更新时间；不限量、未知和零必须区分。
- 连接凭据等高级信息从明确的次级入口访问，默认不铺满首页；账号安全保留独立入口。
- 没有实际联系渠道配置时，使用“联系为你开通服务的管理员”等可执行文字，不造出工单或空客服链接。

**目标旅程：** 接受邀请 → 登录 → 查看服务状态 → 选择客户端并导入 → 连接并验证 → 查看用量 → 必要时管理账号和连接信息。

### 5.3 文案与反馈规范

1. 写“发生了什么、影响什么、下一步做什么”；不在普通提示中写事务、原子兑换、接口来源或“没有写死结论”等自证内容。
2. 主屏保留产品操作语言；技术口径和诊断信息按需查看。对真实风险的说明不得为了简洁而隐藏。
3. 动作按钮必须写实际动作：“重置链接”不能只写“订阅链接”；“复制”只在复制真正成功后反馈。
4. 普通成功反馈短而确定；有等待或失败的操作使用可持续查看的状态，不依赖一闪而过的提示。
5. 字段错误在字段附近；网络/系统故障有页面级恢复入口；全局维护才使用全局通知。
6. 默认中文，保留必要客户端和协议名称；本轮不增加多语言系统或营销内容。

| 现有表达类型 | 目标表达示例（不是实际运行数据） |
|---|---|
| 服务端原子兑换 | 邀请有效。完成注册后将按邀请开通服务。 |
| 规则在面板事务内生效，节点异步分发 | 已保存，正在同步。查看进度。 |
| 403 no proxy access | 当前服务不可用。原因：本周期额度已用完。 |
| 全部取自实际接口，没有写死结论 | 显示真实状态、更新时间和查看详情入口，不再自证。 |
| 硬撤权、运行世代、修订号 | 默认解释为暂停连接、重启或同步；原始术语保留在诊断详情。 |

### 5.4 全局状态与可用性

主路径覆盖加载、空、错误、权限不足、结果未确认、离线和恢复状态。桌面与手机的关键动作可达；支持键盘、明确标签和非纯颜色状态表达。对话框不能靠关闭或刷新才摆脱卡死状态。

### 5.5 验收目标

- 本轮所有 P0/P1 故事具有可复现成功及关键异常证据，检查的是用户可见结果，不只是调用过某个能力。
- 界面主路径、服务保存、节点实际配置、客户端流量、用量账本和权限恢复须相互对应。
- 批量提交丢响应、并发修改、旧回执、坏节点、核心崩溃、上报积压和恢复核对均有失败路径验证。
- 两种前端托管与受保护登录均实际验证；跨 origin 能力若作为支持声明，须另有真实双 origin 验证，不以合成请求替代。
- 兼容性矩阵记录真实客户端版本与组合；不支持、未运行和失败独立列出。允许分片验证，但必须指向同一候选版本和明确前置条件，保留失败与重测关联，不把跨版本结果拼成一次全绿。
- 安全、授权、数据守恒、迁移和主要工作流存在未解决阻断时，不以页面更美观为由交付。

## 6. API 相关约束

**适用。** 保留角色和本人数据边界；读写结果真实，秘密默认不外泄，授权来源与实际生效分离，网络不确定时能核对同一次操作。前后端表达变化不擅自破坏现有调用者；新的能力和兼容变更由后续技术设计说明。本 PRD 不定义端点、字段或存储结构。

## 7. 前端/交互约束

**适用。** 采用专业、克制的控制台表达，重点是信息层级与任务闭环，不另造视觉主题系统。保留现有可用交互基础，不通过隐藏错误、危险操作或高级配置制造“简单”。低保真预览展示的是目标体验和状态，不代表真实运行结果。

## 8. 阶段验收顺序

这是产品交付关卡，不是编码任务清单；实际技术方案和可执行任务在设计阶段拆解。

| 阶段 | 目标 | 进入下一阶段的条件 |
|---|---|---|
| A：需求与目标体验 | 明确范围、术语、两条旅程与异常 | 本草案、用户故事及预览一致，产品选择无未解决冲突 |
| B：可信基础 | 核验整合授权、计量、周期、Agent 与部署候选修复 | 统一候选版本通过基础回归和迁移核对，旧报告不冒充新结果 |
| C：管理员交付 | 接入、配置、开通与结果追踪 | 管理员可在真实环境完整交付，含错误与恢复路径 |
| D：成员使用 | 邀请、导入、状态、用量与账号 | 成员可按指引完成实际连接，核心异常可理解可处理 |
| E：统一验收与交付 | 全链路、安全、故障、升级恢复和说明 | 同一候选版本的证据完整，阻断问题清零，已知边界明确且不伪报完成 |
