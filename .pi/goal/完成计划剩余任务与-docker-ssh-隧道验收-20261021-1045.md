## Acceptance criteria

1. **状态及回归证据可信**：停电后的工作区、构建产物和隔离测试依赖状态得到核实；现有可复用结果与本轮新执行结果分别标注。每项 A01–A16 都有对应的测试入口、工具/核心/客户端版本、结果及证据位置，明确区分真实执行、模拟故障、跳过与范围调整；无依据的“全部通过”不得出现。

2. **A01–A03：身份、授权和批量正确**：自动化验证邀请只能兑换一次、会话撤销、越权拒绝、并发操作不能移除最后一名管理员；继承/覆盖不能绕过停用，无订阅无代理权限，失效预览被拒绝；批量业务原子提交、重复提交幂等，实际多节点部分失败可追踪，重试后状态与实际节点结果一致。

3. **A04–A05：订阅、周期及输出正确**：真实数据库回归证明换订阅不改变订阅链接、不清空用量；周期/时区变更保留当前周期并在约定边界生效，跨界补报和下调额度结果正确。节点组变更传播到对应节点，输出去重且无未授权节点，模板/权限变更不被旧缓存错误掩盖。

4. **A06–A07：真实核心撤权与配置安全**：在 Docker 测试节点及 SSH 隧道链路上，以真实 Xray 验证在线撤权提交后 60 秒内拒绝新连接、终止既有 TCP/UDP 会话；空授权能撤销最后用户。无效配置不替换可用配置，乱序/重试不覆盖新修订，技术回滚不恢复已撤销权限；共享实例影响及未受影响节点状态有实际断言或观测证据。

5. **A08–A10：账本、重启和离线到期可靠**：真实数据库及 Agent 状态测试证明相同批次只入账一次、同 ID 异载荷拒绝、ACK 丢失可重发、基线与待上传队列事务一致；核心/Agent 分别重启无负数或双计，合法历史用量可补报。面板离线时已下发到期仍在 60 秒内收紧；未知撤权显示待同步，恢复后生效；重启/回退不复活旧授权。时钟推进或故障注入必须明确标记，不冒充自然跨月长期运行。

6. **A11：受控故障行为正确**：仅在隔离测试组件和容量受限的测试文件系统中验证队列容量/持久化失败、数据库不可用和 Redis 故障/重建。数据库提交失败不返回计量成功 ACK；Redis 故障不绕过鉴权或丢失 PostgreSQL 账本；不可安全持久化时停止受影响代理并报告，恢复后能协调恢复。不得通过耗尽宿主机磁盘或内存制造故障。

7. **A12：可观测与界面可用**：健康状态能区分面板、数据库/Redis、Agent 和核心；告警去重/恢复及通知队列失败重试有检查结果。真实浏览器验证管理员/成员关键流程、移动布局及代表性加载/错误/空状态，无未处理页面错误。Telegram 仅记录实现与模拟测试结果，实际外部送达明确列为未验收。
