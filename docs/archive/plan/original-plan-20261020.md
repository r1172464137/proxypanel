# 合租代理管理平台完整执行计划

> 修订性质：在原批准计划上汇总后续讨论、查漏补缺、模型分工与实际环境状态，作为后续实施基线。
> 本次任务仅修订文档及复核，不实施应用代码、不安装工具、不修改环境变量、不操作远程服务。
> 不划分“第一版、第二版”；实施顺序仅表示依赖关系，不代表删减完整目标。

## 1. 项目定位、约束与范围

建设供自己和朋友合租使用的代理管理平台，统一管理服务器、节点、成员、订阅、用量和运行状态。

**完成目标：管理员集中维护资源与规则，成员自助获取配置；权限可撤销、用量可核对、执行可追踪、故障可恢复。**

### 1.1 技术基线

- Vue 3 + TypeScript + Vite；管理员端与成员端共享前端工程。
- Go 模块化单体面板 + 自研 Go Agent，不保留 PHP，不引入微服务。
- PostgreSQL 是业务、授权、任务和用量的持久化权威存储。
- Redis 用于缓存、短期状态和限流计数，不存储唯一的授权或用量账本。
- 基于官方 Xray-core，面板不依赖 V2Board/XBoard，节点不依赖 v2node。
- 按此前推荐架构执行：Agent 管理独立 Xray 进程，通过本机管理 API 和配置文件交互；不默认嵌入核心或维护核心分叉。
- 如果确定目标无法通过官方接口实现，先提出能力差距和影响，由负责人组织决策；不能擅自换核心、扩大范围或降低验收要求。
- Agent 本地使用事务型持久化保存配置元数据、采样基线及上报队列，优先考虑 SQLite；这是节点恢复机制，不替代 PostgreSQL。
- 不额外引入消息队列或专用时序数据库。可靠任务使用 PostgreSQL 持久任务/outbox，不把 Redis 当唯一任务队列。

### 1.2 已确定的产品原则

- 私人合租，不做公众商城；管理员创建成员或发邀请。
- 使用“订阅”作为可复用的权限和使用规则，不使用商品套餐、购买和支付语义。
- 每个成员同时绑定一个主要订阅；支持有限的个人覆盖，不做多订阅叠加。
- 同一订阅下的成员不共享订阅令牌、代理凭据和个人配额。
- 暂不启用尚未确认的限速、共享池、设备限制等选项，不做不能生效的占位开关。
- 服务器成本与到期记录属于管理信息，不自动引入收款或费用结算。

### 1.3 明确排除的功能

商城、订单、支付网关、充值余额、优惠券、返佣提现、工单平台、多租户运营、主题/插件市场、通用远程终端、自动追随最新核心、多级权限表达式、全协议全客户端兼容承诺。

共享流量池、跨节点全局限速、中转拓扑、费用分摊账本、流媒体/AI 专项探测不是当前默认范围；需要用户明确选择才纳入。

## 2. 业务模型与统一授权规则

```text
服务器 → Agent → 核心运行实例 → 节点
                                │
                              节点组
                                │
                              订阅规则
                                │
                              成员绑定
                                ├── 个人订阅链接
                                ├── 成员×节点代理凭据
                                ├── 独立用量与配额周期
                                └── 有限个人覆盖
```

- **服务器**：机器档案，含地址、地区、备注、到期日期、可选成本。
- **Agent**：服务器管理实例，具有独立身份和授权范围；重启不改变 Agent 身份。
- **核心运行实例**：可独立启动、停止和回滚的核心进程，记录承载节点及重启影响范围；核心每次启动具有新的运行世代标识。
- **节点**：一个代理入口，含监听、对外地址、协议、传输及安全配置。一台服务器可以承载多个节点，不写死一台机器一个核心进程。
- **节点组**：资源组织单位，可被多个订阅引用；授权输出去重。
- **订阅**：节点组授权、每人配额、重置规则、默认有效期和客户端配置模板。
- **成员绑定**：当前订阅、实际有效期、允许字段的个人覆盖，保留迁移历史。
- **订阅链接**：客户端获取配置的个人访问凭据，不等于订阅规则或代理凭据。
- **代理凭据**：按成员×节点隔离；统计关联稳定的成员/节点 ID，不以可轮换 UUID 作为业务主键。
- **周期与账本**：保存明确的周期边界、实际流量和额度调整，不通过删除历史数据实现“清零”。

### 2.1 唯一授权判定

```text
成员账户启用
且绑定存在且有效
且订阅允许现有成员访问
且成员未超额
且节点允许访问
且节点属于有效订阅授权范围
```

- 面板、订阅输出、Agent 授权快照使用同一套有效权限计算规则及版本，不能各自重新解释。
- 个人覆盖不能绕过停用、到期、订阅暂停、节点禁用等上层限制。
- 无有效订阅的正常成员可以登录查看状态和历史，但不能取得可用节点或代理访问权限。
- 账户停用、代理访问暂停、订阅链接撤销分别建模；停用账户须撤销会话并撤销节点访问。
- 不将短暂健康探测失败直接视作永久撤权；管理禁用状态与观测健康状态分别展示。

### 2.2 硬撤权与已有连接的最低效果

- 硬撤权包含成员停用、代理访问暂停、解绑/移除节点授权、订阅暂停、节点禁用、到期、超额以及旧代理凭据撤销；单独重置订阅链接不属于代理硬撤权。
- 默认验收目标为：Agent 与核心运行正常、控制链路可用时，自面板撤权事务提交起 60 秒内，既拒绝新连接，也终止对应凭据已有的 TCP/UDP 代理会话。超额计时从面板确认入账并提交超额撤权开始，不从未采集的真实流量越界时刻开始。
- 对已下发的到期时刻，在时钟正常的前提下由 Agent 本地执行，即使面板离线，也须在到期后 60 秒内达到同等效果；时钟异常应告警并进入已规定的安全处理流程，不能默默延长权限。
- 如果所选核心 API 只能禁止新连接而不能断开旧连接，须使用停止/按最新授权重建受影响实例等兜底。共享实例可能影响其他成员，应在节点配置启用前明确该策略及影响范围，不等撤权发生后再无限等待确认。
- 撤权超时或兜底失败必须显示失败/未完成并告警，不宣称已撤销。若实测无法达到目标，由负责人提出具体限制供用户决定，不能以“符合核心现状”为由自行降低验收。
- 对离线期间新产生、Agent 尚未获知的撤权，不作 60 秒送达承诺；页面显示待同步和离线时长。恢复通信取得最新授权后 60 秒内完成撤权。该例外不覆盖已知到期限制。

## 3. 完整功能目标

### F01. 成员、邀请与账号安全

- 管理员与普通成员两类角色，管理员也不能通过普通成员接口绕过数据隔离。
- 管理员创建成员；邀请有期限、使用限制、撤销状态，兑换并发安全，不开放自由注册。
- 登录、退出、密码修改/管理员重置、会话撤销、启用、停用、有效期管理。
- 订阅令牌与代理凭据分开轮换；代理凭据支持单节点及成员全部节点范围。
- 成员只能查看自己的配置与用量；管理员可查看授权同步结果，不默认展示所有敏感明文。
- 禁止停用、删除或降级最后一个可用管理员，必须在事务/并发下成立。
- 紧急管理员恢复使用主机本地受控命令，不提供公开恢复后门。

### F02. 订阅规则与继承

订阅配置包含名称、说明、节点组、每人额度/不限量、周期与时区、默认有效期、客户端配置模板及已验证可执行的使用限制。

- 持续继承订阅，不只在创建成员时复制一次配置。
- 个人覆盖限定为明确允许的字段，基础范围为配额与成员有效期；限速只有确认纳入并验证实现后才可覆盖。
- 页面显示字段来源和实际生效值，可恢复继承。
- “允许新绑定”“暂停现有访问”“归档”分开，不共用一个模糊开关。
- 归档前迁移或解除现有绑定，保留历史；有使用关联的记录不直接物理删除。
- 修改默认有效期不改变现有绑定的到期时间，必须使用显式批量操作。
- 每人额度不等于共享流量池，不能混算。

### F03. 批量管理、预览与执行结果

- 批量分配/切换订阅、调整有效期、启用/停用、清除覆盖。
- 凭据轮换和额度调整是单独的危险操作，要求确认及审计。
- 预览显示影响成员、节点、个人覆盖例外，以及已超额/即将到期的后果。
- 预览绑定规则和成员集合版本，提交时检查；发生相关变化则要求重新预览。
- 已用量属于动态值，提交时重新计算超额后果；如果结果改变了确认内容，重新确认，不用每一字节变化无条件锁死操作。
- 提交使用幂等操作标识；规则修改及任务/outbox 在 PostgreSQL 同一事务提交。
- 本项目规模下，选定范围的业务变更原子提交；节点分发异步执行，分别显示等待、应用中、成功、失败与重试。
- 不把“已受理”“规则已保存”显示成“全部节点已生效”。旧任务不得覆盖新规则。

### F04. 服务器、节点组与节点

- 服务器档案、备注、成本、到期日和提醒。
- 节点创建、编辑、排序、启用、停用、维护、删除。
- 明确监听地址与客户端连接地址，管理端口、传输、TLS/REALITY 参数及证书引用。
- 节点组变更传播到所有引用订阅，影响预览和版本机制同样适用。
- 区分服务器/Agent 离线、核心故障和配置未同步。
- 删除/停用节点同步更新订阅输出与核心配置，保留用量历史。
- 核心实例与节点归属明确。重启前显示全部受影响节点与连接；推荐按故障影响范围划分实例，实际资源开销需要验证。

### F05. 自研 Go Agent 与 Xray 生命周期

- 安装、一次性注册、服务托管、启动、停止、升级、卸载；不提供通用 shell。
- Agent 主动连接面板，独立可轮换凭据，不能获取其他服务器的节点信息。
- 拉取版本化配置/授权快照，校验后应用并报告真实回执。
- 支持重试、幂等执行、周期全量核对；明确区分未变更响应和有效空列表。
- 清空最后一个用户必须真正撤权，不能以 `len(users)==0` 当作“没有变化”。
- 动态用户增删优先使用管理 API；配置变更需重启时明确影响，不宣称无损热更新。
- 核心 API 只在本机/受保护通道开放，不在公网暴露。
- 旧响应、乱序任务或旧回执不允许覆盖更高版本；失败回执不推进已生效版本。
- Agent 启动时恢复本地状态、执行已知到期限制，再恢复访问；联网后重新核对授权。

### F06. 配置、证书、升级与回滚

- 配置有版本、来源、内容校验和审计；区分期望、已下载、已生效状态。
- 应用前执行结构和 Xray 配置校验；使用受控替换并保存最近可用技术配置。
- 技术配置与成员授权分别管理；回滚技术配置时必须结合最新授权重建有效配置。
- 无法安全应用最新授权时停止受影响实例并报警，不能恢复含已撤销用户的旧完整配置。
- 处理配置应用成功但回执丢失；重试不重复破坏性操作。
- TLS 证书导入、有效期检查；自动签发方式在具体部署规格中冻结，不默认支持所有 DNS 服务商。
- 固定核心/Agent 版本和下载来源，校验制品完整性；记录已验证兼容范围，不自动追随上游 main。
- 核心/Agent 升级前保留恢复点；失败可回退。数据库升级单独制定迁移和恢复策略，不宣称二进制回退自动回退数据库。

### F07. 订阅链接与客户端配置

- 每人独立链接、复制、二维码、已验证客户端的导入入口。
- 支持显式格式选择；User-Agent 自动识别仅为便利功能。
- 只输出授权且客户端兼容的节点，支持排序、分组、复用分流模板与配置预览。
- 节点、成员、权限及令牌变化后失效相关缓存；缓存键包含授权/模板版本，缓存命中也必须验证当前令牌及访问资格。
- 订阅响应禁止共享代理缓存，敏感令牌在反向代理和应用日志中脱敏。
- 撤销订阅链接只阻止再下载，已下载配置须通过轮换/撤销代理凭据失效。
- 链接复制、二维码及客户端下载信息不泄露其他成员或服务器私钥。
- 客户端支持以固定版本矩阵与真实导入/连接测试为准，不靠格式生成成功宣称兼容。

### F08. 用量、周期与配额

- 按成员、节点、周期查询代理上下行；明确计数方向、字节单位及是否包含协议开销。
- 以选定入口用户计数作为代理计量来源，避免入口出口重复累加；网卡流量独立展示。
- 每个成员有持久化的当前周期起止时间；UTC 存储，周期按明确的业务时区计算。
- 月末、闰年、夏令时/时区切换和停用后恢复不能产生重复或遗漏周期，计算规则写入测试。
- 无论切换订阅，还是直接修改当前订阅的周期规则或时区，都保留成员当前周期起止时间和已用量，新周期规则从下一周期开始；额度变更立即应用。连续修改以生效边界前最后一次合法提交的新规则为准，边界竞争须事务化处理。
- 个人额度覆盖不改变周期。低于已用量的新额度触发超额策略，变更前提示。
- 不提供含糊的“立即改周期并清零”。特殊纠正使用审计化额度调整；历史流量不删除。
- 面板以 PostgreSQL 已确认账本作全局配额判断，超额后撤销授权并显示分发进度。
- 本地轮询、网络延迟及在途数据可能导致超额；离线时不保证跨节点全局额度严格截止。

### F09. 可靠采集与上报

- 记录 Agent 身份、核心运行世代、节点/成员稳定 ID、唯一批次号、采样起止时间、上下行字节数及协议版本。
- 优先使用非破坏性累计计数采样；同一计数源只允许一个采集者，不并发读取清零。
- 采样基线与待上报批次在 Agent 本地同一事务落盘，防止崩溃导致双计或遗漏。
- 核心重启通过新世代区分，Agent 自身重启不无条件重置上次基线；旧世代队列可以继续补报。
- 面板认证并检查 Agent 与节点归属、成员历史映射、非负计数、时间范围和载荷大小。
- 在同一 PostgreSQL 事务中去重、记账、更新周期与相关任务；持久化提交后才返回确认。
- 同一幂等标识但不同载荷必须拒绝并记录异常，不能悄悄当成成功重复包。
- Agent 收到明确确认才清理待发项；超时、HTTP 非成功、业务拒绝都不能当成功。
- 停用、解绑、删除或轮换凭据后，合法历史流量仍可入账，使用历史映射而不是当前授权拒收。
- 补报按发生时间归属，接收时间单独审计；节点时钟漂移需检测，异常时间批次隔离处理，不擅自挪到当前周期。
- 在已知周期边界尽量采样；跨边界区间采用确定的分摊规则并标注为估计，不能声称精确还原每字节时刻。具体误差口径在计量规格中冻结。
- 本地队列设容量与磁盘告警；不得静默丢弃未确认数据。接近无法安全持久化时停止受影响实例并报告，恢复持久化后再恢复，避免无界占用磁盘。
- 核心突然退出到最后成功采样之间仍可能有损失，不能承诺零损耗计量。

### F10. 离线与故障语义

- 面板暂时不可用时，节点继续使用最后一次有效技术配置及已知授权。
- 已下发的到期时间由 Agent 本地执行；新停用指令只能在恢复通信后获知。
- 界面显示最后心跳、最后授权同步、待生效版本，不把离线节点显示为“权限已同步”。
- 配置损坏、权限无法安全应用、持久化失败分别有可解释的错误状态，失败不能自动放宽权限。
- Redis 故障不丢业务事实：授权回查 PostgreSQL；无法查权时安全拒绝；登录限流使用受限本地降级或拒绝，不无限放行。
- PostgreSQL 不可用时不确认新写入和用量上报；Agent 保留队列，面板不以缓存伪造提交成功。

### F11. 监控、事件与通知

- CPU、内存、磁盘、网卡流量、近期趋势；Agent 心跳、核心版本、运行状态和同步状态。
- 区分 Agent 在线、进程运行、端口可达与代理真实握手；记录探测位置与方法。
- 节点异常/恢复、服务器到期、证书到期、磁盘/上报积压告警。
- 告警去重、抑制和恢复事件；至少有站内记录，外部渠道推荐 Telegram，配置后验证实际送达。
- 高频数据有保留期限，历史聚合后清理；具体容量预算、采样频率和保留期在运维规格中锁定。
- 无需默认采集访问网站历史。来源 IP 仅在明确需要的功能中采集，并限制可见范围与保留时间。

### F12. 页面与可用性

- 管理员：总览、服务器、节点、节点组、订阅、成员、用量、事件、任务/同步结果、设置。
- 成员：个人订阅与导入、授权节点、用量/额度/重置时间、凭据管理、使用说明。
- 手机与桌面适配；加载、空状态、错误、重试和无权限状态完整。
- 危险操作显示范围和后果；批量任务有逐对象结果，不能只显示一个成功提示。
- 前端隐藏按钮不是安全控制，所有写入与读取权限均由后端执行。

## 4. 安全、数据与恢复要求

### 4.1 身份与秘密管理

- 密码使用成熟安全哈希；会话支持过期、撤销，敏感账号变更撤销旧会话。
- Cookie 方案落实 HttpOnly、Secure、SameSite 与 CSRF 防护；本地测试与正式 HTTPS 配置分开，不关闭生产防护以迁就开发。
- 注册令牌只能原子兑换一次；Agent 凭据轮换后旧凭据按明确策略失效，不能无限并存。
- 面板对外入口及 Agent 通信使用 HTTPS；TLS 验证不默认跳过。本地测试使用明确受信任的测试 CA/回环限定，不提供生产通用 insecure 开关。
- 面板使用低权限服务账号；Agent 和核心只获得服务管理、监听及文件访问所需的最小权限，不因测试 SSH 使用 root 而让应用默认以 root 运行。
- 数据库应用运行账号采用最小权限。部署迁移账号与应用账号权限应可分离；现有测试账号是测试库所有者，不宣称等同生产最小权限。
- 私钥、证书与代理凭据受控存储，加密主密钥与数据库备份分开保存；日志不记录令牌、密码或完整密钥。
- 成员订阅令牌按可撤销凭据管理，使用高熵随机值与安全的服务端验证方式。
- Agent 不接收任意命令/路径；核心下载来源、配置引用及证书路径受限，避免路径穿越和命令注入。
- 配置预览、探测目标及外部订阅/规则获取若涉及服务端请求，必须做目的地址与重定向限制，避免成为内网请求入口。

### 4.2 数据保留与删除

- 成员/节点/订阅删除采用受控归档或墓碑，保留合法历史上报所需映射与审计，不级联抹掉账本。
- 用量批次去重记录不能早于允许重放/补报窗口清理；如使用序列水位压缩，必须保留拒绝旧批次和检测冲突的能力。
- 管理操作、配置变更、授权、凭据轮换、额度调整、升级和恢复均有审计记录，不记录秘密值。
- 明确数据保留期限与磁盘预算；清理任务限于本项目，不执行全局清理。

### 4.3 备份、恢复与面板回退

- PostgreSQL 迁移有版本及执行锁；备份记录数据库版本、迁移版本、配置版本和恢复步骤。
- 恢复旧备份后进入恢复协调状态：暂停普通变更及向节点推送旧权限，先核对节点状态、授权版本和账本，再显式恢复同步。
- Agent 已知更高授权版本时不得因面板恢复而接受旧授权；恢复后使用明确的控制面世代/重建流程，不能简单把旧版本号加一掩盖历史缺失。
- 不能确认安全授权的节点停止受影响访问或保留已知更严格状态，不从旧备份重新放行已撤销成员。
- 已确认上报可以在约定窗口保留可重放副本/回执索引，以配合恢复对账；不保证无限期保存。
- 恢复保证受实际 RPO/RTO、备份频率、WAL/归档策略和可重放窗口约束，实施前写明并演练。
- 没有覆盖故障窗口的 WAL、备份或 Agent 副本时，相关数据无法凭空恢复，必须报告缺口，不宣称“无损恢复”。
- 二进制升级、数据库迁移和密钥恢复分别验证；不在共享数据库主机上进行主机级故障注入。

### 7.1 角色和模型

| 角色 | 指定模型 | 职责 |
| --- | --- | --- |
| 总负责人 | 当前主 Agent（我） | 对接用户、控制范围、公共契约、任务拆分、集成、权限控制、最后验收 |

- 用户决策由主 Agent 汇总提出；子 Agent 的意见是输入，不是批准。

| 任务 | 独占写入范围 | 约束 |
| --- | --- | --- |
| 产品规格 | 主负责人指定的 `docs/specs/` 文档 | 不修改冻结计划或公共契约；交付后由负责人核对 |
| 研发 A：面板 | `cmd/panel/`、`internal/panel/`、`migrations/` 及模块内测试 | 只通过已冻结契约与 Agent/前端协作 |
| 研发 B：Agent | `cmd/agent/`、`internal/agent/` 及模块内测试 | 不接触面板数据库，不获取远程 root 凭据 |

| 主负责人 | `internal/contracts/`、`api/`、根依赖/锁文件、`configs/`、`deploy/`、集成测试协调 | 共享依赖修改先汇报，由负责人串行合并 |

| Sol 审查 | 只读指定代码、契约、测试和变更 | 不改实现，不将静态阅读冒充测试执行 |

- 同一文件不允许多个任务同时修改，根 `go.mod/go.sum` 由负责人串行更新。
- 所有权可以在任务结束后移交，不能在子 Agent 运行中暗中修改其文件。
- 测试数据库的 schema/key 前缀和端口按运行分配；禁止多个任务并行迁移/清理共享 schema。
- 子 Agent 默认没有远程管理权限；必要数据库访问由负责人提供受限测试配置，不传播 SSH 私钥。
- 遇到契约变化先暂停受影响接口工作，更新版本和样例后继续，不各写一套临时协议。

### 7.3 Review 与测试流程

1. 研发完成单元测试、自检，提交文件清单、行为变化、测试命令/结果与未完成项。
2. 主负责人整合并执行构建、类型检查、基础集成，消除无法编译和接口错位。
3. Sol 使用测试任务权限运行针对性测试；新增测试使用有写入权限且限定范围的任务，不能假定只读 reviewer 能执行 shell。
4. Sol 对已集成的非平凡变更进行一次集中独立只读审查，不与修改并发。
5. 每条问题提供严重度、文件位置、触发条件、实际影响、建议回归测试；不把纯风格偏好或猜测列为阻塞。
6. 主负责人判断并分配具体修复；补测试、重新执行受影响回归，不反复开启全量审查或模型辩论。
7. 存在越权、撤权失效、凭据泄漏、重复计量/丢账或不可恢复的高影响缺陷时不能宣布完成；明确报告未解决项。

重点审查权限隔离、继承与批量事务、空列表撤权、缓存失效、周期补报、崩溃窗口、配置回滚、秘密泄漏以及测试是否真正覆盖行为。
