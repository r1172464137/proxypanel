# 前端文案规范与改写清单

审理范围：`web/src/views/**/*.vue` 全量 —— 47 段页面说明、25 段字段帮助、64 个表单标签。
逐条按"一个不懂 Xray、不懂后端的人能不能看懂"来判。

---

## 一、四类问题

### 类 1 · 把实现细节当说明（最普遍）

说明里写的是"系统内部怎么运转"，用户需要的是"这页能干什么、我该注意什么"。

| 现状 | 问题 |
|---|---|
| 只有 succeeded 且**回执版本匹配**才算生效 | 暴露状态机内部概念 |
| 提交后**逐对象异步下发** | 异步是实现细节 |
| 兑换为**原子操作** | 技术术语 |
| 告警**去重与恢复事件由服务端维护** | 用户不关心谁维护 |
| **锚点日 / 时区仅对下一周期生效** | 用户要知道"什么时候变"，不是字段名 |
| 计量以**账本**为准 | "账本"是内部表名 |

### 类 2 · 裸字段名当标签（节点编辑器，38 个里 30 个）

```
decryption        flow              disableInsecureEncryption
settings.password settings.network  fallbacks（JSON 数组）
tlsSettings.serverName  tlsSettings.alpn
certificates[0].certificateFile     realitySettings.dest
shortIds          settings.spiderX  server_key
```

对比 3x-ui：那里叫「加密」「流控」「额外ID」「传输协议」「伪装域名」。

### 类 3 · 有歧义或会误导

| 位置 | 现状 | 问题 |
|---|---|---|
| 成员表单 | 启用个人覆盖（关闭即恢复继承订阅默认配额） | **勾上但不填 = 不限量**，界面没提 |
| 服务器 | 成本（最小货币单位） | 用户不知道填"500"是 5 元还是 500 元 |
| 设置 | 默认业务时区 | "业务"是内部说法，就是"时区" |
| 用量 | 起始时间 / 结束时间 | 没说时间范围作用在哪个字段 |
| 成员表单 | 有效期（到期时间） | 括号里是同义反复 |
| 节点 | 对外地址 / 监听地址 | 两个"地址"没区分清楚用途 |
| 用量帮助 | 若后端尚未实现该筛选，结果会包含全部周期 | 把未实现的功能写在界面上 |

### 类 4 · 危险操作没写后果

| 位置 | 现状 | 缺什么 |
|---|---|---|
| 成员表单 | 账户启用（停用会撤销会话） | 没说"该成员正在用的代理会立刻断" |
| 成员表单 | 允许代理访问（关闭会硬撤权） | "硬撤权"是黑话 |
| 凭据页 | 轮换代理凭据 | 没说"所有设备要重新导入，连接立刻断" |
| 节点 | 保存后默认重启该节点的独立核心实例 | "核心实例"是内部分层 |

## 二、改写原则

1. **先说结果，再说条件**。"停用后该成员立刻无法连接，需重新登录。"而不是"停用会撤销会话"。
2. **标签用人话，字段名进括号或 tooltip**。「加密方式」而不是 `decryption`；真要保留原名就写成「加密方式（decryption）」。
3. **说明不超过两句**，第一句是什么，第二句是注意事项。
4. **危险操作必须写三步**：现在会发生什么、你原有的东西会怎样、怎么恢复。
5. **不写"服务端""原子""幂等""回执""账本""代际"** 这类词，除非该页就是给运维看的（任务页可以保留一部分，但要解释）。
6. **数字要带单位**。`GiB`、`天`、`元`，不写"最小货币单位"。
7. **留空语义必须显式写出**。留空=不限量 / 留空=跟随订阅 / 留空=默认。

## 三、改写清单

### 3.1 页面说明（47 → 精简约 30 条，删重复）

每个页面只保留一段说明（列表页与弹窗内不再重复）。改写后示例：

| 页面 | 现状 | 改为 |
|---|---|---|
| 总览 | 面板实时聚合值；节点/Agent 的实际生效状态请以任务与运行时页面为准。 | 一屏看关键数字。这些是面板的即时统计；节点是否真的在跑，请看「服务器 → 运行时」。 |
| 服务器 | 机器档案与 Agent 注册入口。注册码一次性、15 分钟内有效。 | 一台机器一条记录。登记后生成注册码，拿到那台机器上装 Agent，它就会向这里报到。注册码只能用一次，15 分钟内有效。 |
| 节点 | 节点是代理入口：协议、传输、安全与客户端参数分别编辑；保存后默认重启该节点的独立核心实例。 | 节点就是一条代理线路。改完保存会让这条线路短暂断开（约数秒），正在用的连接会重连。 |
| 订阅 | 授权规则集合：节点组、每人配额、月周期与时区、默认有效期、访问开关。影响已有成员的修改需预览确认。 | 订阅决定"哪些人能用哪些节点、每人多少流量、多久重置一次"。改了会影响已在用的人，所以要你先看一遍影响再确认。 |
| 成员 | 账户状态、代理访问、订阅绑定与额度覆盖互相独立；批量操作必须先预览影响再提交。 | 成员能不能登录、能不能用代理、有多少流量，是三件独立的事。 |
| 任务与同步 | 下发/应用/回执状态。只有 succeeded 且回执版本等于期望版本才算"已生效"；timeout 会告警。 | 你改的东西要送到节点上才算真的生效。这里看每一条送到哪一步了；标红的需要重试。 |
| 用量 | 按成员/节点/时间查询。计量以账本为准；跨周期补报按采样区间分摊并标注估计值… | 按成员或节点查流量。数字来自实际计费记录；补报的历史数据会标注"估算"。 |
| 凭据 | 订阅链接与代理凭据分开管理：轮换链接只阻止再次下载；轮换代理凭据会硬撤权并中断连接。 | 见 3.3 单列。 |

（其余按同一风格改写，逐条记录在实现时同步更新本文件。）

### 3.3 「凭据」页重做（单独说明）

现状：一个标题"凭据"，里面混了两件不同的事。

改为两块，各自带一句话：

```
订阅链接
  一个网址。把它粘进客户端（v2rayN / sing-box / Mihomo）就能拿到节点列表。
  泄露后果：别人能拿到你的节点配置。换掉它（轮换）后旧网址失效，
  但已经导入客户端的配置仍然可用，正在用的连接不会断。

节点密码
  每个节点各自的 UUID 或密码，由面板自动生成并发给客户端，这里不显示。
  泄露后果：别人能直接用你的流量。
  换掉它（轮换）后所有设备立刻断开，必须重新导入订阅才能恢复。
```

「轮换节点密码」折叠进危险操作区，带二次确认。

### 3.4 危险操作文案模板

统一格式：**会发生什么 → 你的东西会怎样 → 怎么恢复**

- 停用账户：
  「停用后该成员立刻无法登录，正在使用代理的连接会断开。重新启用后可恢复，但需要重新登录。」
- 关闭代理访问：
  「关闭后该成员的所有代理连接立即断开，客户端连不上。重新开启后需要重新拉取订阅。」
- 轮换节点密码：
  「所有已导入的客户端配置立刻失效，正在使用的连接会断开。换完必须重新导入订阅才能恢复。」
- 删除节点：
  「节点上正在使用的连接会断开，使用该节点的订阅会少一条线路。此操作不可撤销。」

### 3.5 配额覆盖改交互

现状：输入框 + 复选框，勾上不填 = 不限量（未提示）。

改为单选：

```
流量额度
  ○ 跟随订阅（当前 100 GiB）
  ● 单独设置   [ ____ ] GiB    留空 = 不限量
```

## 四、验收方式

1. 改完后用真实浏览器逐页抓取全部可见文本，与上一版做 diff，确认：
   - 不再出现 `no_binding` / `succeeded` / `原子` / `幂等` / `回执` / `账本` / `代际` / `硬撤权` 等词（任务页允许保留但要有解释）
   - 不再出现裸字段名（`tlsSettings.` / `realitySettings.` / `settings.`）
   - 每个危险操作都有"会发生什么/怎么恢复"
2. 1440 / 390 双分辨率无溢出。
3. 前端测试补到覆盖关键文案（用 `expect(text).toContain('...')` 锁定人话版本，防止回退）。
