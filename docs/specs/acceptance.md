## 1. 环境等级与判定规则

| 等级 | 含义 | 当前可用性 |
| --- | --- | --- |
| **E0** | 单元/模拟：可控时钟、注入失败、伪造载荷；无真实核心 | 可执行（需工具链就位） |
| **E1** | 本机真实链路：真实 Xray 核心、真实 PostgreSQL/Redis（SSH 隧道到 `127.0.0.1:15432/16379`）、真实测试客户端、多个 Agent 进程/端口模拟多节点 | 依赖本机 Go 工具链与隧道；同一主机的多进程**不等于**真实多机网络 |
| **E2** | Linux 部署：systemd、权限、安装/卸载、核心进程恢复、发布矩阵 | **未授权/未准备环境，未验证** |
| **E3** | 公网与真实客户端：域名、证书签发、REALITY 目标、NAT/IPv6、运营商、手机客户端、长期运行 | **未授权，未验证** |

判定规则：

1. 每个场景写明**最低等级**；低于该等级的结果不能替代。
2. 只有实际执行并记录证据才算“通过”；未执行写 `未验证`，不得写“应当通过”。
3. 报告分开标注：`模拟通过` / `本机真实链路通过` / `Linux 部署通过` / `公网通过`。
4. 涉及时间阈值（60 秒）的场景：单次达标不足以判通过，需 ≥5 次（冷/热各若干）且记录最大值。
5. 涉及“拒绝/断开”的场景：只允许用**真实客户端行为**判定（连接失败、无数据回包、FIN/RST），不得用 API 200 或数据库布尔值代替。
6. 测试数据使用运行标识前缀（如 `run-<uuid>`）与专属 schema/key 前缀；不得 `FLUSHALL`、不得 `DROP DATABASE`、不得操作原 axonhub 资源（见 `docs/test-databases.md`）。

| 场景 | 代码版本 | 工具/核心/客户端版本 | 环境等级 | 命令或操作 | 实测结果 | 证据路径 | 结论 |

## 7. AC-REVOKE（计划 §2.2 硬撤权，**核心验收**）

### 7.1 AC-REVOKE-01 硬撤权 60 秒（新连接拒绝 + 已有 TCP/UDP 会话终止）

| 项 | 内容 |
| --- | --- |
| 等级 | **E1 必须**（E2/E3 另行复测）；E0 只能验证“版本/装载/判定”逻辑，不能判定 60 秒 |
| 前置 | 1 台服务器 1 个核心实例 1 个启用节点（协议组合须在已确认矩阵内）；成员 M 有 1 条 TCP 长连接 + 1 条 UDP 会话（如持续 `ping`/短报文）；面板与 Agent 心跳正常（记录上一轮心跳时延） |
| 操作 | 管理员停用 M（或暂停代理访问），记录面板事务提交时刻 `revoked_at` |
| 观测 | ①客户端持续 TCP 收发探针（间隔 ≤1s）；②客户端 UDP 探针同样；③另起客户端尝试新建连接；④面板任务/回执显示 `applied_at` 与版本 |
| 判定 | `revoked_at → 收到 RST/FIN 或无数据回包` ≤ **60s** **且** `revoked_at → 新连接被拒绝（认证失败/连接被拒，不得成功转发数据）` ≤ 60s **且** 回执版本 = 期望版本 |
| 失败判据 | 任一方向 >60s；90s 时仍能继续收发数据；只有 `pending/applying` 就显示“已生效”；回执版本落后 |
| 重复 | ≥5 次（含冷启动 Agent 与热路径各若干），记录最大值与分布 |
| 证据 | 客户端报文日志（含时间戳）、面板 `revoked_at`/`applied_at`、Agent 回执 JSON、核心管理 API 用户列表截图/导出 |

补充子场景：

| ID | 变量 | 期望 |
| --- | --- | --- |
| AC-REVOKE-02 | 触发源 = 成员停用 / 代理暂停 / 订阅暂停 / 节点禁用 / 解绑（逐个执行） | 每种都在 60s 内达标，且只影响对应范围 |
| AC-REVOKE-03 | 触发源 = 超额（低配额 + 可控流量） | 计时起点为账本提交时刻（非流量越界时刻），60s 内达标；页面显示超额原因 |
| AC-REVOKE-04 | 触发源 = 旧代理凭据轮换（单节点 / 全部节点） | 旧凭据会话 60s 内断开；其他成员不受影响；订阅链接不变 |
| AC-REVOKE-05 | 共享实例影响面 | 同实例其他成员在撤权过程中掉线时长被记录并展示；若使用实例重建兜底，需在下发前已知该策略 |
| AC-REVOKE-06 | 兜底路径 | 核心 API 只能拒新连接时，Agent 采用停止/按最新授权重建实例；记录重建耗时与影响成员数 | 60s 内旧会话不可继续转发 |
| AC-REVOKE-07 | 超时显示 | 人为阻断 Agent 应用（如挂起进程/回执丢弃） | 页面显示“未完成/超时”+ 告警事件；**不得**显示“已撤销” |
| AC-REVOKE-08 | 已知到期本地执行 | 下发 `expires_at` 后将面板离线（断隧道/停面板进程） | 到期后 60s 内断开；面板恢复后状态一致，显示“本地执行” |
| AC-REVOKE-09 | 离线期间的新撤权 | Agent 离线 5 分钟，期间停用成员 M；恢复通信 | 恢复后 60s 内完成；页面在离线期间显示“待同步/离线时长”，不承诺 60s |

### 9.1 AC-REPORT-01 **幂等流量入账（同一批次只入账一次）**

| 项 | 内容 |
| --- | --- |
| 等级 | E1（E0 可先验证去重逻辑） |
| 步骤 | ①Agent 采集 1 个批次（含成员×节点、上下行字节、采样起止、`batch_id`）；②正常上报 → `accepted`；③**原样重发**同一 `batch_id` 3 次；④并发再发 2 次（同 `batch_id`） |
| 期望 | 第 1 次 `accepted` 且账本增加 X 字节；后续全部 `duplicate`，返回首次结果引用，账本增量仍为 X；Agent 清理该批次本地记录；审计/指标记录 duplicate 次数 |
| 失败判据 | 账本出现 2X；返回 5xx 导致 Agent 无限重试；重复入账但被当作新批次 |
| 证据 | 账本查询前后值、响应 JSON、Agent 队列状态 |

### 9.2 AC-REPORT-02 **同 ID 异载荷必须拒绝**

| 项 | 内容 |

| 失败判据 | 静默按“重复”成功返回；或用新载荷覆盖旧入账 |
