## 你提的 4 点，逐条确认结果

### 1. `no_binding` 直接显示原始代码 —— 确认，且比你说的更广

我在 `MeSubscriptionView` 加了中文映射，但**其余 4 处仍直接打印代码**：

| `MemberDetailView.vue:199` | 同上 |

这是我修得不彻底：只改了新加的无权限区块，没统一收口。

**根因**：映射表写在了视图里，而不是共享模块。应该有一个
`web/src/lib/accessReasons.ts`，所有展示访问原因的地方都调它。

### 2. "凭据"页看不懂 —— 确认

页面标题就叫"凭据"，但内容是两件不同的事混在一起：

- **订阅令牌 / 订阅链接**：一个 URL，贴进客户端就能拿到节点列表
- **代理凭据**：每个节点各自的 UUID / 密码，由服务端注入，页面不显示明文

对普通成员来说"凭据"是个空词。页面里还有"轮换代理凭据（全部节点 / 单个节点）"
这种只有运维才懂的操作。

**根因**：术语没落地。需要把"这是什么 / 我什么时候会用到 / 泄露了会怎样"
用一句话写清楚，并考虑把危险的"轮换代理凭据"从成员页移走或折叠。

### 3. 设置页很多未知字段 —— 确认

`SettingsView.vue` 直接把 `template_defaults` 的 JSON 塞进 `JsonEditor`，
旁边写着"服务端未返回模板默认值字段（template_defaults / templates /
default_templates）。为避免覆盖未知结构，本页不提交该字段"。

这是**把后端的数据结构问题暴露给用户**。普通管理员不该看到 JSON 编辑器。

### 4. 新建节点页易用性差 —— 确认，这是最严重的

节点编辑器把 **30 多个 Xray 内部字段名直接当表单标签**：

```
decryption          disableInsecureEncryption    settings.password（服务端密钥）
tlsSettings.alpn    realitySettings.dest         server_key
shortIds            settings.spiderX             fallbacks（JSON 数组）
tlsSettings.serverName   settings.fingerprint    ...
```

对比 3x-ui / mihomo 面板的常见做法，缺的是：

| 缺什么 | 3x-ui 类的做法 |
|---|---|
| 协议选完自动填默认值 | 选 VLESS 自动填 `decryption: none`；选 SS 自动填 cipher 下拉 |
| 密钥自动生成 | UUID、SS 密码、REALITY 密钥对、shortId 都能一键生成 |
| 传输选完出现对应字段 | 只有选了 ws 才出现 path/host；选了 reality 才出现公钥 |
| 内置预设模板 | "VLESS+REALITY"、"VLESS+WS+TLS" 一键套用 |
| 字段说明 | 每个输入框下方一句话解释，而不是字段名 |
| 校验与提示 | 端口占用、必填、格式错误即时提示 |
| 证书处理 | 自签证书一键生成，不用手写 PEM |

## 补充：术语问题清单（来自实机提问）

以下都是"用户看不懂/会误操作"的具体点，归入阶段 B 处理。

### B5 配额覆盖（`MembersView.vue:448`）

现状文案：`启用个人覆盖（关闭即恢复继承订阅默认配额）`

三个问题：
1. 没说清"不勾就是跟着订阅走"，用户不知道默认行为；
2. **勾上但不填数字 = 不限量**（`EffectiveQuota` 里 `overrideQuota == nil` 返回
   `nil, "override"`），这是危险行为，界面完全没提示；
3. "覆盖""继承"是数据库/编程词。

建议改为单选：
```
流量额度
  ○ 跟随订阅（当前：100 GiB）
  ● 单独设置 → [____] GiB
    留空 = 不限量
```

### B6 页面说明写成"系统实现"而不是"用户能做什么"

| 页面 | 现状 | 问题 |
|---|---|---|
| 任务与同步 | "只有 succeeded 且回执版本匹配才算生效" | 暴露状态机内部 |
| 批量任务 | "逐对象异步下发" | 异步是实现细节 |
| 邀请 | "兑换为原子操作；列表不展示 code" | "原子操作"是术语 |
| 事件与告警 | "告警去重与恢复事件由服务端维护" | 用户不关心谁维护 |

原则：说明里写"这页干什么、什么时候用、注意什么"，不写内部机制。

### B7 其它已确认的术语问题

- 「凭据」页：两件事混在一起（订阅链接 vs 代理凭据），见 B2
- 5 处 `no_binding` 等原始代码直接显示（只有 1 处已修）
- 节点编辑器 30+ 裸字段名（`decryption`、`disableInsecureEncryption`、
  `settings.password（服务端密钥）`），见阶段 C

### B8 「轮换代理凭据」的定位

这个操作会**换掉 UUID/密码**，导致：
- 该成员所有已导入客户端的配置立刻失效
- 所有在用连接被硬切断
- 必须重新拉订阅并重新导入才能恢复

与「轮换订阅链接」的区别：后者只换 URL，已导入的配置和现有连接都不受影响。

结论：这是运维手段而不是自助功能，建议从成员页移到管理员页，或折叠进
危险操作区并写明后果。
